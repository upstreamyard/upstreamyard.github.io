Security & quality

Every image meets the same standards.

One pipeline and one set of rules for every project. Nothing is published before it passes its tests, and you can check all of it yourself.

Signed, with SBOM and provenance

Keyless cosign signatures from GitHub Actions on every image and chart; an SBOM and SLSA provenance on every image.

Non-root by default

Every image runs as UID 10001; where the app allows it, with a read-only root filesystem.

Verified upstream sources

Built from release tags, or from official archives checked against SHA-512 sums and GPG signatures. Upstream code is never patched.

Smoke-tested before publishing

Each image starts against its real dependencies, such as PostgreSQL, Redis or MySQL, before it is pushed.

Charts installed for real

Every chart change is installed in a Kubernetes cluster in CI and must pass helm test.

Your data stays yours

Charts never bundle databases. You bring your own PostgreSQL, Redis or S3, managed the way you already manage them.

Don't take our word for it. Every Dockerfile, chart, build log and test run is public on GitHub.

FAQ

Common questions

Are the images and charts really free?

Yes. The Dockerfiles, scripts and Helm charts are open source under Apache-2.0, and the images are public on Docker Hub and GHCR. Each application keeps its own upstream license.

Are you affiliated with the upstream projects?

No. upstreamyard images and charts are community-maintained. We build from the projects' official releases and never patch their code; bugs we find are reported upstream.

How can I verify an image before I run it?

Every image is signed keylessly in GitHub Actions and carries an SBOM and SLSA provenance:

cosign verify upstreamyard/<image>:<tag> \
  --certificate-identity-regexp '^https://github.com/upstreamyard/<image>/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
Can I suggest a project for the catalog?

Yes. Write to us with the project's name and a link to its releases. New images and charts go through the same process as the existing ones: built from official releases, signed and tested.

How quickly do new upstream releases reach the images?

Every image repository checks for new releases daily. A new release is built, smoke-tested, signed and published automatically, and the matching chart update is tested in Kubernetes before it is released.
